# Decisions (starting set)

These are the starting decisions. Change one only by adding a new row with a date and a reason.

| ID | Decision |
|---|---|
| D-01 | Pilot college is our own college. Multi college design from day one. |
| D-02 | First scope: sign in, college spaces, verification, admin console, profile and portfolio, Team Finder, Application Tracker, announcements, curated opportunities. Stretch: Lost and Found, roster import. |
| D-03 | Plan length is 10 build days. If a day is not finished, work continues next day and is reported in Slack. |
| D-04 | Modular monolith (one Next.js app plus Supabase). |
| D-05 | Team decides by talking, then majority vote. Area owner breaks ties. Security and isolation checks are not voted. |
| D-06 | Login by email code. Phone OTP is not proof of being a student. Verification: college email domain, invite code, manual approval. |
| D-07 | No payments. |
| D-08 | No AI features for users in v1. AI is only used to help us build, under the AI rules. |
| D-09 | Opportunities are added by hand by admins. No scraping. |
| D-10 | Later phases: marketplace, notes, events, activities, skill exchange, resume, roadmap, daily plan, interview practice, reputation, cross college network, anonymous posts, student ID upload. |
| D-11 | Hosting: free plans for building and staging with fake data. Real students need a paid plan with backups and a plan that allows commercial use. R5 checks the official pages on Day 1. |
| D-12 | Git: GitHub Flow with short branches and one pull request per task. |
| D-13 | Tenancy: shared tables with `college_id` and Row Level Security. Pages under `/c/{slug}`. |
| D-14 | UI is built in code with shadcn/ui and Tailwind. No Figma. |
| D-15 | Database and login: Supabase. |
| D-16 | Search: Postgres full text search. |
| D-17 | Tests: Vitest, Playwright with axe, pgTAP, k6 (small). |
| D-18 | Code licence: private repository, all rights reserved, until the owners decide with legal advice. |
| D-19 | Slack is the team chat. GitHub is for code. |
| D-20 | Content Security Policy allows inline scripts and styles (`'unsafe-inline'`), everything else is strict. Reason: nonce based CSP needs every page rendered per request, which does not work with our prerendered pages (Cache Components). Revisit with Subresource Integrity when stable. Owner: R2 |
| D-21 | Clean up and expiry run through one safe function `maintenance_run` that a scheduler calls over HTTP (`POST /api/internal/maintenance`, shared secret). Not pg_cron. Join requests expire after 30 days. Owner: R2 |
| D-22 | Opportunities belong to one college and are curated by moderators and admins (no platform wide list yet). Deadline reminders go out once per saved listing and deadline date, 48 hours before, unless the person switched them off. Owner: R2 |
| D-23 | Reads are limited to 300 a minute per person. A tab a college switched off (`features.campus`, `collaborate`, `career`) answers 404 FEATURE_DISABLED in the API. Avatars: JPEG, PNG, WebP, GIF, AVIF only, 2 MB, no SVG. Owner: R2 |
| D-26 | 2026-11-10. R3 **Day 4 (projects and public portfolio) is deferred** to after the first release: no backend exists for it (PRJ-01 to PRJ-06), nobody owns that backend, and a public page needs a privacy review first. R3 does Days 5, 6 and 7 next. |
| D-27 | 2026-11-10. **Posting to Global needs no new backend.** Global is a normal college space. "Post to My college or Global" (D-25) means the post is created in that space (`POST /c/{slug}/team-posts` with the slug of the college or `global`). A student can be a member of a college and of Global at the same time, and sees each space's posts in that space. Nothing is visible across colleges. |
| D-28 | 2026-11-11. **Compact UI scale.** The page base size is 14px (14.5px on phones) and the fixed pixel text sizes were reduced by one step. The earlier large scale (16px base) felt oversized on phone and desktop. Touch targets stay at least 40px. |
| D-29 | 2026-11-11. **The redesign: one dark world, one brand gradient, a feed first app.** The look of StudentOS changes completely. One dark theme (no light theme), one brand gradient (violet, magenta, blue) used for the main action, the mark and a few highlights, and nothing else coloured. Plans are cards with a gradient cover, ideas are calm text cards, and the first screen of every space is a Home feed of both. On a phone the navigation is a glass dock (Home, Plans, Ideas, You) with a separate create button; on a desktop it is a quiet sidebar. Fonts are Bricolage Grotesque (headings) and DM Sans (text). The old rules "no glass, no gradients, no rounded-xl, 44px targets" are replaced (see docs/DESIGN_SYSTEM.md, Design system v2). Why: the first look was a calm editorial look that students found boring and large; most students use a phone. |
| D-30 | 2026-11-11. **A college is created with a one-time setup code from the platform owner.** The owner makes an 8 digit code (`supabase/production/create-setup-code.sql`), only its hash is stored, it works once and expires (14 days by default, 30 at most). A signed-in person who enters it on `/setup` makes their college and becomes its first admin (COL-01). Five tries an hour per person. A wrong, used and expired code all answer the same 403. Colleges stay separate by row level security in one database (a separate database per college is not possible on the free plan and is not needed for isolation). |
| D-31 | 2026-11-11. **Careers becomes a placeholder.** The tracker and opportunities are big and not needed for the first closed beta. The Careers tab says "coming soon" with a Notify me button that remembers the wish on the device. The code, the tables and the API stay, so nothing is lost; the browser tests for it are skipped until it comes back. |
| D-32 | 2026-11-11. **Ideas and sports.** Ideas (short text posts with votes and one level of replies) are a new feature, and Team Finder gets two kinds (sport, event) with a start time and a place, because most students plan a match or an event, not a startup. Ideas can be removed by their author or a moderator; reporting an idea is not built yet (see the status note). |
| D-33 | 2026-11-11. **Events, Lost and found and the Marketplace are built, without payments.** Events have a start time, a place, an optional capacity and RSVPs. Lost and found and the Marketplace share one table (`board_posts`) with two boards and kinds. Contact is private and inside the app: messages between the person who posted and each person who wrote (no phone number or email is ever shown, and no photo upload yet). Prices are whole rupees and only shown, nothing is paid inside StudentOS. Payments come later as their own decision. Reporting a post is not built yet; the author or a moderator can remove it. |
| D-34 | 2026-11-12. **The owner dashboard.** The platform owner has a dashboard at `/owner` (later `admin.<domain>`). Three locks: a signed-in account on the allow-list `platform_admins`, an owner PIN (12 or more characters, stored only as a salted scrypt hash, made by `pnpm owner:pin`), and a 30 minute unlock cookie signed by the server. Everyone else gets the normal "not found" page. Five wrong PIN tries lock it for 15 minutes and 20 in a day lock it for the day. Every change asks for the PIN again and every action is written to the audit trail. It is made of server pages and server actions (no public API), so the browser never holds a secret key. Version 1: overview, colleges, setup codes, users, reports, health, audit. An authenticator app can be added as a second factor later. |
| D-35 | 2026-11-12. **The functional round.** (1) Ideas are "Thoughts": only some text is needed, like a message to a friend. (2) A plan can have open join (one tap), the host is told who joined and the people who joined see who is in. (3) Events are official (college admins and moderators, inside a college) or personal (students, in Global) and can be invite only. Every feature can be posted to "My college" or "Global". (4) Moderators, admins and the owner can remove any plan, thought, event or listing, and must pick a reason that is sent to the author. (5) Speed: the app runs in the same region as the database, and screens show what they already know at once. Payments stay for later. |
| D-36 | 2026-11-12. **Turf and court booking.** A directory of venues and booking requests that the venue's manager confirms by hand and the student is told. The manager is the person who added the venue, plus the admins and moderators of that college. In a college only admins and moderators add venues, in Global anyone can. Two confirmed bookings never overlap. Payments come later. |
| D-38 | 2026-11-12. **Any member can add a venue.** Turf and courts followed the events rule (admins only inside a college), but everything else a student can start is open to any member, so adding a venue is too. The person who adds it manages its requests, and a college's admins and moderators can manage and hide any venue of their college. Migration 20261120000000. |
| D-39 | 2026-11-12. **Onboarding and a richer profile.** A new person goes through a short tour: name, a unique username, sex (with "prefer not to say"), birth year (optional), casual and technical interests (at least three), one line about what excites them, and an optional mobile number. Name, username, sex and interests are required. Under 18 is allowed. Sex, birth year and the number are private and live in a closed table, never in `profiles`. The number is optional now (it may become required later), is shown only to the host of a plan the person joined and chose to share it with, and hides a day after the plan. It is not verified yet. |
| D-40 | 2026-11-12. **Reports for everything, and feedback.** Buzz, comments, events, listings and venues can be reported and hidden from the queue like plans and profiles. Anyone can send feedback from the app; the owner reads it in the dashboard. |
| D-41 | 2026-11-12. **Disappearing messages, text only.** Classmates of one college can message each other. A message disappears 1 hour after it is opened, or 3 days after it was sent if never opened. No photos in messages. Reporting copies the recent messages into the report, because they will be gone. Blocking applies. |
| D-42 | 2026-11-12. **Photos are shrunk on the phone and kept in Storage.** One photo on a market or lost and found post: about 1080 pixels wide, WebP, 1 MB at most, camera metadata removed. The database keeps only the path. Avatars are shrunk the same way. |
| D-43 | 2026-11-12. **People can unblock, and the owner sees counts only.** Settings lists the people I blocked with an Unblock button (RPT-05). The owner dashboard shows how many finished the tour, answers by option, age bands, popular interests and how many share a number with hosts. It never shows one person's sex, birth year or number. |
| D-44 | 2026-11-13. **Gender is private unless the person shows it.** The screens say Gender (the stored field is still `sex`). A switch in Edit profile, off by default, puts it on the profile for classmates. "Prefer not to say" is never shown. Skills are called Strengths in the app; the API and Team Finder still use skills. |
| D-45 | 2026-11-13. **Age can be shown too, as years.** A switch in Edit profile (off by default) shows the age in years on the profile. The birth year is never shown. Home shows the latest college notice for colleges with Campus. People has interest filters, people who share my interests first, and a Message button on every card. |
| D-46 | 2026-11-13. **College, branch and year are on every profile.** The person types the college (so Global shows where people come from) and the graduation year, and may add a branch. College and year are required in the welcome tour. All are shown on the profile. |
| D-47 | 2026-11-13. **Turf, Lost and found and the Marketplace are for one campus.** Global does not offer them (screens, create list, home feed) and their addresses send a person home. Events and the weekly challenge stay. |
| D-48 | 2026-11-13. **Invite links and following.** Everyone has an invite link (`/?ref=code`). It is counted once when the new person finishes the tour. Following is one way and needs no approval. Message requests and groups come later. |
| D-49 | 2026-11-13. **Polls and a question of the day on Buzz.** A poll has 2 to 4 options and can be changed. |
| D-50 | 2026-11-13. **Anonymous posts and comments.** Others see Anonymous and an animal (steady inside one buzz). Moderators and the database keep the real author. No adult content. Anonymous posts never count towards contributions. |
| D-52 | 2026-11-13. **Contributions and badges on the profile.** Counts of what a person gave (buzz, replies, plans, events, upvotes received, challenges, friends invited), never anonymous posts. Badges are worked out from the counts and reward giving, not volume. |
| D-53 | 2026-11-13. **The owner sees the whole user record, and can delete many users at once.** The owner dashboard Users page shows each person's login, profile, college, gender, birth year, number, interests and contributions (the owner runs the platform). Every visit is audit logged. Tick boxes pick people, and one confirmed action (PIN and a tick) deletes them for good. Owner accounts are skipped. |
| D-54 | 2026-11-13. **Topic debates replace the weekly challenge.** Anyone starts a debate: a question, two sides, a topic (movies, sports, tech, campus, politics, music, food, other) and an end time (1 hour to a week). People pick a side, argue under it (also anonymously) and upvote the strong points. It closes by itself: the state is worked out from the clock, nothing runs. The side with more people wins. Debates and arguments can be reported and hidden like everything else. 3 debates a day and 30 arguments an hour per person. |
| D-55 | 2026-11-13. **Contributions count debates.** Debates started plus arguments made (never anonymous ones) replace challenges in the contributions and badges on a profile. |
| D-56 | 2026-11-13. **Who follows whom is private.** A person sees their own followers and following lists (and counts). Other people's profiles show no counts, only whether the viewer follows that person. |
| D-57 | 2026-11-13. **College names are checked and suggested.** The app cannot know that a typed college is real. It refuses plain nonsense (too short, mostly symbols, repeated letters, keyboard runs, words like test or none), suggests names that already exist while typing, and the owner can search every typed name in the Users page. |
| D-58 | 2026-11-13. **The question of the day is gone.** Home shows the most active live debate instead. Contributions are the last card of a profile: two groups of numbers, badges as medals, and progress to the next badge. |
| D-59 | 2026-11-13. **Standing has to be earned.** The profile shows a level (Newcomer, Contributor, Regular, Trusted, Respected, Pillar) built from what other people got from the person: upvotes received, debates that drew 8 or more people, plans where 3 or more were accepted, events with 8 or more going, friends who joined and finished the tour. Posting volume counts almost nothing (replies stop at 50 points). Levels from Regular up also need days as a member. Badges are rare and show what they take. The server only counts (`profile_contributions`); levels and badges are worked out in the app so they can be tuned without a migration. Other people see the same panel. |
| D-60 | 2026-11-13. **People is called Network.** The page has a search over name, username, headline, college, branch and interests, three tabs (Everyone, Similar to you, My college) and an interests filter in a sheet. Cards show the person, the college line and how many interests are in common, no chip clouds. The address is still /people. |
| D-37 | 2026-11-12. **Comment likes, public reach and a calmer UI.** A comment can be liked or disliked like a buzz. A post made in the public space (Global) is shown to everyone: every college feed also shows it, with a Public tag. Everyone is added to the public space automatically, so a student can post publicly from their own college. Filters float as a small pill and no longer cut the screen with a full-width strip. |
| D-25 | 2026-11-08. Who comes into the app: anyone can sign in (email code, or Continue with Google). Then the person joins **their college** (college email, invite code, manual approval) or **Global**. Global is one special college with the open join method: active at once at level 1, not verified by any college, with limited features (no Campus tab) and posting limits. Only Global may use the open method (a database trigger enforces it). **Audience of posts (decided, built with Collaborate):** when a student creates a project, team post or event, they choose **My college** or **Global**. A Global post is visible to Global members and to every college member; a college post only to that college. Reason: not every college has a college email or is on StudentOS, and students want to team up across colleges. |
| D-24 | Colleges are created in production with `supabase/production/create-college.sql` until a platform admin exists (ADM-01). "Confirm email" is on in staging and production. Deleting an account is immediate after an emailed code (no grace period yet). Owner: R2 |
| D-61 | 2026-11-13. **Messages start as requests.** A first message to someone with no chat is a request. The receiver chooses Continue chatting or Not interested. A request lasts 3 days. After Not interested the sender can ask again after 5 days. Mutual followers skip requests. Caps: 10 new requests a day, 3 for accounts under 2 days old. |
| D-62 | 2026-11-13. **Network strength.** Connections (accepted chats and mutual follows) count towards tiers at 3, 6, 10, 20, 35, 50, 75 and 100, shown on Home with people to meet and one-tap openers. Rewards come after launch. |
| D-63 | 2026-11-13. **Private debates.** A debate can be invite only (1 to 50 people). Only the author and the invited see it. The author can invite more while it is live. |
| D-64 | 2026-11-13. **Place on the profile.** An optional city or area, with the same plain checks as the college name. |
| D-65 | 2026-11-13. **The owner Users page is complete and paged.** It shows the whole record per user (including place, network and activity) 50 at a time with the total, and the Overview shows network, debate and request numbers. Group chat for plans is not built. |
| D-66 | 2026-11-13. **The owner can see who is behind anonymous posts.** Other students only see Anonymous and an animal, but the owner dashboard has an Anonymous page (every anonymous buzz, comment and debate argument with name, username, email, college, reports) and the Reports page shows what was reported and who wrote it, also when it was anonymous. Each visit to the Anonymous page is written to the audit log. Buzz in a list can be reported without opening it. |
| D-67 | 2026-11-13. **Debate cards show a taste of the discussion.** Each debate carries its strongest argument (most strong-point votes, then newest), never with an author, so an anonymous point stays anonymous. The liveliest live debate (at least 3 people) is lifted above the list as Hot right now. Once I have joined, the two sides shrink to a slim row. |
| D-68 | 2026-11-13. **Updates, team requests and feedback were rebuilt.** Every notification type now leads somewhere (a debate invite opens the debate), the list refreshes by itself and is grouped by day with an Unread tab. "My requests" is now Team requests: people asking to join my posts are answered right on the page (Accept or Decline), mine show a coloured status, and withdrawing asks first. Feedback keeps a half written note on the device and sends the page the person came from, which they can leave out. |
| D-69 | 2026-11-13. **New placement.** Your profile is the picture in the top right of the phone header (Messages, Notifications, picture). The bottom dock is Home, Plans, Buzz, Debates, Network, with the + button unchanged beside it. The open tab is shown by a brighter icon and label, with no background. A one-time tip says the profile moved. On desktop the profile is in the account menu. |
| D-70 | 2026-11-13. **The + shortcuts were rebuilt.** Holding or double tapping + opens one glass panel: Waiting for you (Messages, Team requests, Notifications, each with its count), Campus (Events, Turf and courts, Lost and found, Marketplace; only Events in Global), then Invite friends and Send feedback. Debates and Network left it because they are tabs now. The + button shows a count of messages and notifications waiting. The tips use one glass component with a countdown line, a close button and an exit animation; the profile tip comes first and the + tip waits for it. |
| D-71 | 2026-11-13. **A guided tour, and a clearer Create card.** The tour starts by itself on a person's first open (remembered on the device), nine short cards: welcome, Plans, Buzz, Debates, Network, the + button (with the double tap picture), messages and updates, profile, and where to replay it. A lit up hole glides to each thing and a glass card sits beside it; tapping the card goes on, Skip leaves. It can be replayed from a faint ? beside Messages and from How to use StudentOS in the + shortcuts. The Create card is one deep clear glass card that grows out of the + button, with white text that stays readable over any page. Panels no longer animate a blur, so they open without a stutter. |
| D-72 | 2026-11-13. **Launch scope: Global only.** The choice screen shows My college locked as Coming soon with a note: the college space keeps everything inside the college, nothing goes public, and it opens campus by campus as we team up with colleges. The Marketplace (payments are out of this launch) and Lost and found (only works inside one campus) show a Coming soon page that says what they are for, in every space, with Soon tags in the chips, the Create card and the shortcuts. One switch per feature in `src/lib/features.ts`. Finishing the welcome tour now shows a busy button, waits at most 1.5 s for the invite count, reads the profile back to confirm it is finished, and if the next page still reads it as unfinished it asks again a few times before sending anyone back (a stale answer used to bounce people to the welcome page until a reload). |
| D-73 | 2026-11-14. **A chat stays in the list when its messages disappear.** Messages vanish 1 hour after they are opened (3 days if never opened), but the conversation with the person stays, so people can write again. The list says "No messages right now" for an empty chat and sorts by the last time anything was said. |
| D-74 | 2026-11-14. **Phone and desktop alerts.** A person turns on alerts per device (Settings, or the card on Updates). Every new notification is sent once to their devices with the Web Push standard (no app store, no extra cost). It works on Android and desktop browsers, and on iPhone once StudentOS is added to the Home Screen. Alerts are sent right after a change is saved and by a scheduler every minute as a safety net. The words are the notification's own title and message, never a private message's text. Turned off unless the two VAPID keys are set. |
| D-75 | 2026-11-14. **StudentOS is installed as an app from the browser, with no app store.** The landing page has one Download the app button. On Android and desktop Chrome or Edge it opens the real install prompt; on iPhone it shows Share, then Add to Home Screen. The installed app opens full screen with its own icon and can receive alerts. New logo: a glass sphere with two overlapping glass rings (no letters) (`public/logo.svg`, `src/components/app/logo.tsx`), used for the site, the app icons and the favicon. The Google Play and App Store buttons were removed. |
| D-76 | 2026-11-14. **Alerts follow the person, not the phone.** Signing out removes this device from alerts, and Sign out everywhere removes all of the person's devices, so the next person on a shared phone never gets someone else's alerts. Settings has a Send test alert button (PSH-03) for checking that alerts reach the device. |
| D-77 | 2026-11-14. **Alerts are asked for inside the app, and asked again kindly.** Once a person is settled (after the welcome steps, tour and tips), a card offers Turn on alerts; the browser's own prompt only appears after they tap it, because browsers punish prompts nobody asked for. After Not now it returns after 2, 5, 10 and 21 days, then every 21 days; if the browser blocked alerts it explains how to allow them on the same schedule; on iPhone it explains Add to Home Screen. It stops once alerts are on. The landing page says Add to your phone (nothing downloads) with a note that a downloadable Android app is launching soon. The status bar icon is a one-colour logo (`public/badge.png`), because Android turns coloured icons into a white dot. |
| D-78 | 2026-11-14. **Blocked alerts get a guide, and invites read like an invitation.** Browsers do not let a site ask again after a person said no, so the alerts bar and Settings show Show me how: steps for Chrome, an installed Android app, iPhone and desktop, and a button that tries again as soon as the person has allowed it (it also notices when they come back to the app). The share message for invite links says what StudentOS is, that it is free and that it can be added to a phone in two taps. |
