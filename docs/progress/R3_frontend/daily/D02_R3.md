What I learned today: Next.js 16 Partial Prerendering (PPR) requires asynchronous route parameters (`params: Promise<{ slug: string }>`) to be resolved inside `<Suspense>` boundaries to avoid blocking prerendering. Accessible error handling requires linking input controls via `aria-describedby` and announcing failures with `role="alert"` in `ErrorSummary`. Keeping the API toggle behind a single exported boolean flag simplifies early UI validation before backend integration is merged.
